# llamafactory框架大模型指令微调（一）：数据集准备

# 大模型训练与微调

在自然语言处理领域，大语言模型（Large Language Models, LLMs）的开发和部署通常涉及两个关键阶段：**预训练（Pre-training）**和**微调（Fine-tuning）**。理解这两个概念及其区别，以及微调的不同方式，对于有效使用大模型至关重要。

## 1. 什么是大模型训练？

**大模型训练** 通常指 **预训练（Pre-training）** 阶段，即从零开始构建一个大型语言模型的过程。

- **目标**：让模型学习语言的通用知识、语法、语义、事实和推理能力。
- **数据**：使用海量的、多样化的无标注文本数据（如互联网网页、书籍、论文等），规模可达TB级甚至PB级。
- **方法**：通过自监督学习（如语言建模任务，预测下一个词）来训练模型参数。
- **计算资源**：极其庞大，需要数千块高性能GPU/TPU，训练时间长达数周甚至数月，耗资数百万美元。
- **产出**：得到一个**基础模型（Base Model）**，如GPT-3、LLaMA、Qwen等，具备广泛的知识和生成能力，但未针对特定任务优化。

## 2. 什么是大模型微调？

**大模型微调** 是在预训练模型的基础上，使用相对较小的特定任务数据集，对模型参数进行**进一步训练**，使其适应下游任务的过程。

- **目标**：将通用模型适配到特定领域（如法律、医疗）或任务（如对话、翻译、情感分析）。
- **数据**：少量（通常几千到几万条）高质量的标注数据，与目标任务密切相关。
- **方法**：在预训练模型权重上继续训练，通常使用监督学习。
- **计算资源**：相比预训练，微调需要的资源大幅减少，单块或多块消费级GPU即可完成。
- **产出**：得到一个**指令微调模型（Instruction-tuned Model）**或**领域适配模型**，在特定任务上表现更优。

## 3. 大模型训练与微调的区别

| 维度 | 预训练（训练） | 微调 |
|------|----------------|------|
| **起始点** | 随机初始化参数 | 加载预训练权重 |
| **数据规模** | 海量（TB级）通用数据 | 较小（MB/GB级）特定任务数据 |
| **计算成本** | 极高（数千GPU天） | 较低（几到几十GPU小时） |
| **目的** | 学习通用语言知识 | 适配特定任务/领域 |
| **参数更新** | 更新全部参数 | 可能更新全部或部分参数 |
| **产出模型** | 基础模型（Base） | 微调模型（Fine-tuned） |

简单来说：**预训练是“上大学”，微调是“岗前培训”**。

## 4. 大模型微调的分类及区别

根据微调过程中**更新参数的策略**，可以将微调分为多种类型。主要分为：**全参数微调**和**参数高效微调**两大类。

### 4.1 全参数微调（Full Fine-tuning）

- **原理**：对预训练模型的所有参数进行更新。
- **优点**：理论上能达到最优的适配效果，因为模型所有部分都能针对新任务调整。
- **缺点**：
  - 计算和存储成本高：需要存储和更新整个模型的梯度，显存占用大。
  - 容易过拟合：当任务数据量较小时，可能破坏预训练学到的通用知识。
  - 部署成本高：每个任务都需要保存一份完整的模型副本（数十GB）。
- **适用场景**：数据量充足、计算资源丰富、需要极致性能的任务。

### 4.2 参数高效微调（Parameter-Efficient Fine-Tuning, PEFT）

PEFT旨在只更新少量额外参数，而冻结大部分预训练参数，大幅降低计算和存储成本。常见PEFT方法包括：

#### 4.2.1 LoRA（Low-Rank Adaptation，低秩适配）
- **原理**：在预训练模型的某些层（如注意力机制的Q、V矩阵）旁路添加低秩矩阵（即 `W = W0 + BA`），训练时只更新这些低秩矩阵的参数，原始权重冻结。
- **参数量**：通常只更新原模型参数的0.1%~1%。
- **优点**：
  - 训练速度快，显存占用低。
  - 无推理延迟：训练完成后，可将低秩矩阵合并回原权重，推理时无额外开销。
  - 支持模块化切换：多个LoRA模块可以独立训练并动态加载，方便多任务部署。
- **缺点**：相比全参数微调，可能略微损失性能，但通常非常接近。
- **代表工具**：HuggingFace PEFT、LLaMAFactory。

#### 4.2.2 Adapter（适配器）
- **原理**：在Transformer的每个层中插入小型的前馈网络模块（Adapter），训练时只更新这些Adapter参数。
- **参数量**：类似LoRA，新增参数约0.5%~5%。
- **优点**：模块化，易于添加新任务。
- **缺点**：推理时会引入额外层，增加推理延迟（因为Adapter串联在模型中）。
- **适用场景**：对推理延迟不敏感的任务。

#### 4.2.3 Prefix Tuning / P-Tuning
- **原理**：在输入序列前添加一组可训练的连续向量（称为“前缀”或“提示”），这些向量不改变原始模型结构，只更新这些前缀参数。
- **参数量**：极小，通常只有几千到几万个参数。
- **优点**：参数量极少，几乎不占用显存。
- **缺点**：
  - 性能通常低于LoRA或Adapter。
  - 优化难度较大，需要精细调参。
  - 会占用输入序列长度（因为前缀是输入的一部分）。
- **适用场景**：资源极度受限，或需要极快速切换任务的场景。

#### 4.2.4 IA3（Infused Adapter by Inhibiting and Amplifying Inner Activations）
- **原理**：学习对模型内部激活值进行缩放（通过可训练的向量），类似对特征进行加权。
- **参数量**：非常少。
- **优点**：简单高效，效果与LoRA相当。
- **缺点**：较新，社区支持可能不如LoRA广泛。

## 5. 微调总结

| 微调方法 | 参数量 | 训练显存 | 推理延迟 | 性能 | 适用场景 |
|----------|--------|----------|----------|------|----------|
| 全参数微调 | 100% | 高 | 无变化 | 最高（数据充足时） | 数据量大、资源多、追求极致 |
| LoRA | 极少（0.1~1%） | 低 | 无增加 | 接近全参数 | 通用首选，平衡性能与成本 |
| Adapter | 较少（0.5~5%） | 中 | 增加 | 较好 | 可接受推理延迟的场景 |
| Prefix Tuning | 极微量 | 极低 | 无增加 | 中等 | 资源极限受限，快速任务切换 |

# LoRA指令微调的数据集制作指南

在进行LoRA（低秩适配）指令微调时，数据集的质量和格式直接影响最终模型的效果。本文将详细介绍指令微调（Supervised Fine-Tuning, SFT）所需的数据集结构、格式要求、构建步骤以及在LLaMAFactory框架中的注册方法。

## 1. 指令微调数据集的基本概念

指令微调的核心是让模型学会遵循人类的指令来生成回答。因此，数据集通常包含**指令（instruction）**、**输入（input）**（可选）和**输出（output）**三个部分，或者以多轮对话的形式呈现。常见的格式有 **Alpaca格式** 和 **ShareGPT格式**，其中Alpaca格式更简单，适合单轮指令任务；ShareGPT格式支持多轮对话历史。

## 2. 数据集格式详解

### 2.1 Alpaca格式（推荐用于单轮指令微调）

Alpaca格式是一个JSON文件，包含一个对象列表，每个对象有三个字段：

- `instruction`：描述任务或指令的文本。
- `input`：可选的上下文或输入，如果没有可以为空字符串。
- `output`：模型应输出的理想回答。
---
三个字段的常规用途

在指令微调（Instruction Fine‑tuning）的数据集里，这三个字段通常扮演如下角色：

| 字段 | 含义 | 常见用法示例 |
|------|------|-------------|
| **`instruction`** | 任务描述或用户指令，告诉模型要“做什么”。 | `“将下列句子翻译成英文。”` |
| **`input`** | **可选**的输入内容，即指令作用的具体数据。 | `“今天天气很好。”` |
| **`output`** | **期望**的模型输出，即正确答案或理想回复。 | `“The weather is nice today.”` |

组合起来的**训练样本构建方式**一般为：

- 若有 `input`，则拼接为：  
  `{instruction}\n\n{input}` → 模型需生成 `{output}`  
- 若无 `input`（即 `input` 为空字符串），则只用：  
  `{instruction}` → 模型需生成 `{output}`

**示例**：
```json
[
  {
    "instruction": "解释什么是机器学习？",
    "input": "",
    "output": "机器学习是一门人工智能的科学，它使计算机能够通过经验自动改进..."
  },
  {
    "instruction": "将以下句子翻译成英文",
    "input": "今天天气真好",
    "output": "The weather is nice today."
  }
]
```

### 2.2 ShareGPT格式（支持多轮对话）

ShareGPT格式更复杂，适合微调对话模型。它包含一个对话列表，每个元素是一个对话轮次，包含 `from`（角色）和 `value`（内容）。常见角色有 `human` 和 `gpt`。整个数据集是一个JSON文件，其中每个条目是一个对话列表。

**示例**：
```json
[
  [
    {
      "from": "human",
      "value": "你好，请问你是谁？"
    },
    {
      "from": "gpt",
      "value": "你好！我是Qwen，一个AI助手，很高兴为你服务。"
    },
    {
      "from": "human",
      "value": "解释一下机器学习。"
    },
    {
      "from": "gpt",
      "value": "机器学习是一门人工智能的科学，它使计算机能够通过经验自动改进..."
    }
  ]
]
```

在LLaMAFactory中，通过 `dataset_info.json` 中的 `columns` 映射来适配这两种格式。

## 3. 数据集构建步骤

### 3.1 数据收集
根据你的目标任务收集文本数据。常见来源：
- 公开数据集：如Alpaca、Dolly、GPT4All等。
- 自建数据：根据业务场景编写问答对。
- 日志数据：清洗历史对话记录。

### 3.2 数据清洗与格式化
- **去重**：删除完全相同的问答对，避免模型过拟合重复内容。
- **质量筛选**：检查回答是否准确、完整、无偏见。
- **格式化**：将数据转换为Alpaca或ShareGPT格式，确保字段名统一。

### 3.3 划分训练集与验证集
建议将数据集按一定比例（如90%训练，10%验证）划分，以便监控训练过程。可以分别保存为 `train.json` 和 `val.json`，并在注册时分别指定。

### 3.4 在LLaMAFactory中注册数据集

1. **放置数据文件**：将你的数据集JSON文件放入 `LLaMA-Factory/data/` 目录下。
2. **编辑 `dataset_info.json`**：在该文件中添加新数据集的描述。该文件位于 `data/` 目录下，包含所有可用数据集的元信息。

**示例注册Alpaca格式**：
```json
{
  "my_custom_data": {
    "file_name": "my_custom_data.json",
    "columns": {
      "prompt": "instruction",
      "query": "input",
      "response": "output"
    }
  }
}
```
- `file_name`：数据文件名。
- `columns`：将原始JSON字段映射到框架内部字段。`prompt` 对应指令，`query` 对应输入，`response` 对应输出。

**示例注册ShareGPT格式**：
```json
{
  "my_multi_turn_data": {
    "file_name": "my_multi_turn.json",
    "formatting": "sharegpt",
    "columns": {
      "messages": "conversations"
    },
    "tags": {
      "role_tag": "from",
      "content_tag": "value",
      "user_tag": "human",
      "assistant_tag": "gpt"
    }
  }
}
```
- `formatting`：指定为 `sharegpt`。
- `columns`：映射消息字段，这里 `messages` 对应数据中的对话列表字段名（本例中为 `conversations`）。
- `tags`：定义角色标签和内容标签，以及用户和助手的角色名称。

### 3.5 验证数据集格式
可以使用LLaMAFactory提供的脚本检查数据集是否可正确加载。在项目根目录运行：
```bash
python src/llamafactory/data/loader.py --dataset my_custom_data
```
如果没有报错，说明数据集已正确注册。

## 4. 数据集注意事项

### 4.1 指令清晰度
指令应明确具体，避免模糊。例如“写一首诗”不如“写一首描写春天的五言绝句”效果好。

### 4.2 输入与输出的对应
如果有输入（如翻译的源句子），确保输出正确对应。避免指令中已经包含输入信息，导致字段冗余。

### 4.3 数据多样性
涵盖多种任务类型，避免模型只学会单一模式。

### 4.4 长度控制
根据模型的最大上下文长度（如2048 tokens），确保每条数据的总长度不超过该值。LLaMAFactory训练时会自动截断，但过长数据可能导致信息丢失。可以通过 `cutoff_len` 参数统一截断。

### 4.5 多轮对话的连贯性
在ShareGPT格式中，确保对话轮次逻辑连贯，避免跳跃或缺失上下文。

## 6. 总结

制作一个高质量的指令微调数据集需要：
- 明确的目标任务和数据来源；
- 遵循Alpaca或ShareGPT格式；
- 清洗、去重、划分；
- 在 `dataset_info.json` 中正确注册；
- 验证数据集可加载。

# 指令微调数据集的规模选择指南

在进行指令微调（尤其是像Qwen3-1.7B这样的小型模型）时，数据集的规模直接影响微调效果和训练效率。没有一个绝对的数字适合所有任务，但我们可以根据经验法则和影响因素来确定一个合适的范围。

## 1. 一般规模范围

根据大量实践和研究，指令微调数据集的大小通常在 **几千到几十万条** 之间。具体分类：

- **小型数据集**：500～5,000条
  - 适合**特定简单任务**（如情感分类、邮件生成、固定格式翻译）。
  - 在LoRA等参数高效微调下，即使只有几百条质量高的数据，也能观察到明显的行为改变。

- **中型数据集**：5,000～50,000条
  - 覆盖**多任务指令微调**（如通用对话助手），包含多种指令类型和领域。
  - 这是最常用的规模，例如Alpaca数据集（52k）、Dolly（15k）等。

- **大型数据集**：50,000～200,000+条
  - 用于训练**高度通用**的指令跟随模型，追求更强的泛化能力和复杂推理。
  - 例如UltraChat（200k）、LIMA（1k高质量）则证明高质量小数据也能有效。

**注意**：Qwen3-1.7B参数量较小，对数据量的需求相对较低，通常几千到一两万条数据即可取得良好效果。

## 2. 影响数据集规模的关键因素

### 2.1 任务复杂度与多样性
- **简单任务**（如分类、短文本生成）：500～2000条高质量数据即可。
- **复杂任务**（如多步推理、代码生成、创意写作）：需要更多样化的数据，建议5000条以上。

### 2.2 模型规模
- 模型越大（如7B、13B），通常需要更多数据来充分微调；反之，小模型（1.7B）数据效率更高，小数据集也能快速适应。
- LoRA等PEFT方法由于只更新少量参数，数据需求比全参数微调低。

### 2.3 数据质量
- **高质量数据**（准确、多样、格式规范）可以大幅降低数量要求。例如，LIMA仅用1000条精心筛选的数据就达到了很好的效果。
- **低质量数据**（重复、噪声、格式混乱）则需要更多数量来弥补。

### 2.4 预期泛化能力
- 如果希望模型在**训练集之外的指令**上也能表现良好，需要数据覆盖更多指令类型和场景，数量需增加。
- 如果只需在**固定任务**上表现好（如公司内部问答），小数据集即可。

## 3. 数据集过小或过大的影响

### 数据集过小（<500条）
- **风险**：过拟合，模型只会机械记忆，无法泛化到未见指令；可能产生“鹦鹉学舌”现象，重复训练数据中的内容。
- **应对**：使用更强的正则化（如LoRA秩设低、dropout增大）、早停、数据增强（如回译、改写）。

### 数据集过大（>100k条）
- **收益递减**：当数据量超过一定阈值，继续增加带来的性能提升变小，但训练时间线性增长。
- **噪声引入**：自动收集的大规模数据可能包含错误或低质量样本，需要清洗。
- **资源浪费**：对于LoRA微调，训练时间增加，但效果未必成比例提升。

## 4. 如何判断数据集是否足够

### 4.1 监控训练曲线
- 观察训练损失和验证损失：如果验证损失持续下降并趋于稳定，说明数据量可能足够；如果验证损失很快上升（过拟合），可能需要更多数据或更强正则化。

### 4.2 人工评估
- 在训练集外准备一组测试指令（来自同一分布但未见过），评估模型输出质量。
- 如果模型在测试指令上表现良好，且与训练样本中的回答风格一致但内容新颖，说明泛化能力好。

### 4.3 经验法则
- **对于新任务**：从1000条高质量数据开始，评估效果，再决定是否增加。
- **对于通用指令模型**：参考开源数据集规模，如Alpaca（52k）或Dolly（15k），可根据需求裁剪。

## 5. 实际建议：为Qwen3-1.7B准备数据

结合你的场景（LLaMAFactory + Qwen3-1.7B + LoRA），建议如下：

- **起步阶段**：准备 **1000～3000条** 精心设计的指令-输出对。确保指令覆盖主要任务类型，输出准确、风格统一。
- **效果评估**：微调后，用20%未参与训练的数据（或单独构建的测试集）进行人工/自动评估。
- **迭代扩充**：如果模型在未见指令上表现不佳，逐步增加数据，特别是失败案例对应的新指令。目标规模可在 **5000～15000条** 之间。

## 6. 数据量不足时的策略

如果你的任务数据难以收集到足够数量，可以尝试：

- **数据增强**：使用大模型（如GPT-4）生成更多类似指令-输出对，或对现有数据进行改写、回译。
- **迁移学习**：先在公开通用指令数据集（如Alpaca）上微调，再在小规模领域数据上二次微调。
- **提高数据质量**：精细筛选和人工修正，用高质量替代数量。

## 总结

指令微调数据集的合适规模是一个平衡问题：**质量优先，数量次之**。对于Qwen3-1.7B和LoRA，**1000～10000条高质量数据**通常足以获得显著的效果提升。关键是根据具体任务迭代测试，找到“够用”的点，而不是盲目追求数量。
